How it works

  1. Label an issuePut Factory_go on a GitHub issue or a whole epic. That is the only label you set.
  2. Questions firstThe Foundry asks its open questions on the issue, up front. Answer them, or reply /defaults to take its recommendations.
  3. Plan, code, test, reviewEach story gets a plan with a risk score, a review of the plan, code on its own feature branch, tests, a code review by a second model, and docs.
  4. Merged, once a day to mainFinished stories merge into develop. Once a day you get one pull request from develop to main to merge.

Why teams use it

  • Hands-off, with you in control

    Every plan gets a risk score from 0 to 100. Risky plans wait for your approval; stories that are too big are split into smaller ones.

  • Always clear what happens next

    Home shows what waits for you. The board shows where every story is and why. A health line says when something is wrong with the Foundry itself.

  • Several stories at once

    Runs lock the parts of the code they change, so stories in different areas are built in parallel without merge conflicts.

  • Two agents, any model

    Steps run on Claude Code or the Codex CLI, on Anthropic, OpenAI or local models such as Ollama and LM Studio. One vendor's model reviews the other's work.

  • Your own flows

    Work is described as flows: YAML pipelines of agent steps, shell steps, approvals and branches. Edit them visually, reuse blocks, or let any AI assistant write one.

  • Safe by default

    Every run works in its own copy of the code. Pushes to protected branches and pushes that contain secrets are blocked. Approval steps, budgets and sandboxing when you want them.

  • See everything

    Live logs, readable transcripts of every agent step, diffs, a dashboard of costs, and resume, retry and approve buttons.

  • Turn ideas into stories

    Refinement helps you write good stories with an AI architect that reads your code, asks the right questions and checks each draft against your Definition of Ready.

  • Accounts and roles

    An admin makes flows, watchers and settings. Users run the flows the admin published, on their own repositories, and see only their own runs.

Built for the way you already work

The Foundry follows gitflow: each story on its own feature branch, merged into develop when it is done, and one release pull request a day to main. It reads your issues, comments on them, and labels them so you can follow every story on GitHub too.

It runs on your own Mac, with your own accounts for Claude Code, Codex and GitHub. Your code and your keys stay with you.
