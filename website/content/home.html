How it works

  1. Ask for a changePut Factory_go on a GitHub issue or a whole epic. Or press + New change, write what you want in one box and press Make a plan.
  2. Questions firstThe Foundry asks its open questions up front. Answer them, or take its suggestions (/defaults on GitHub).
  3. Plan, build, checkEach change gets a plan with a risk score and checks you can try, a review of the plan, code on its own feature branch, tests and a code review by a second model.
  4. Delivered, once a day to mainFinished changes merge into develop. Once a day you get one pull request from develop to main to merge.

Why teams use it

  • Hands-off, with you in control

    Every plan gets a risk score from 0 to 100. Risky plans wait for your approval; changes that are too big are split into smaller ones.

  • Plans you can check

    The plan keeps what you asked apart from what it assumed, and you can correct an assumption before anything is built. It writes checks you can try: Works, or Not quite to send it back.

  • Always clear what happens next

    Today shows what waits for you. Each change shows five phases: Understand, Plan, Build, Check and Deliver. Releases shows when each epic will be finished.

  • Not only for developers

    The Simple view shows your projects in plain words: questions as cards, results to check, and a guide that sets up a first project. No logs, branches or costs.

  • Ask Foundry

    The help assistant in the app explains, in your own words, how the Foundry works and what your work is doing. It changes nothing unless you confirm.

  • Several changes at once

    Runs lock the parts of the code they change, so changes in different areas are built in parallel without merge conflicts.

  • Two agents, any model

    Steps run on Claude Code or the Codex CLI, on Anthropic, OpenAI or local models such as Ollama and LM Studio. One vendor's model reviews the other's work.

  • Your own flows

    Work is described as flows: YAML pipelines of agent steps, shell steps, approvals and branches. Edit them visually, reuse blocks, or let any AI assistant write one.

  • Safe by default

    Every run works in its own copy of the code. Pushes to protected branches and pushes that contain secrets are blocked. Safe points show the recent versions that worked, with Restore.

  • Costs in bounds

    A dashboard of costs, and spending limits per run, per day, per issue, per month and per workspace.

  • Teams on one machine

    Users see only their own work. Workspaces keep teams apart on one shared Mac: every step sandboxed, with their own credentials.

  • Five looks

    Calm, Midnight, Friendly, Editorial or Bento, light or dark. Each person picks their own look under Appearance.

Built for the way you already work

The Foundry follows gitflow: each change on its own feature branch, merged into develop when it is done, and one release pull request a day to main. It reads your issues, comments on them, and labels them so you can follow every change on GitHub too.

It runs on your own Mac, with your own accounts for Claude Code, Codex and GitHub. Your code and your keys stay with you.
